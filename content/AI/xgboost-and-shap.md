一位朋友用 XGBoost 做房价预测，测试集误差很小。评审时，对方指着一套房问：同一片区，为什么这套的预测价比旁边高 8%？

他打开 `feature_importances_`，排第一的是收入中位数。对方说，我问的是这一套。

这两个问题不是同一个问题。前者问模型整体依赖什么，后者问某一条预测是怎么被推出来的。XGBoost 自带的重要性只能回答前者，而且回答得并不完整；SHAP 补的是后者，并且对树模型有一个精确、快速的算法。

## 一、两个问题，两种答案

| 问题 | 常用工具 | 输出粒度 | 能否加总回单条预测 |
| --- | --- | --- | --- |
| 模型整体依赖哪些特征 | `gain`、`weight`、`cover` | 一个特征一个数 | 不能 |
| 这一条为什么这样预测 | Tree SHAP | 每条样本、每个特征一个数 | 能，且严格可加 |

`gain` 是分裂带来的损失下降总和，`weight` 是分裂次数，`cover` 是分裂覆盖的样本权重。[XGBoost 参数文档](https://xgboost.readthedocs.io/en/stable/parameter.html) 三者都在描述“树是怎么长出来的”，没有定义“某一行的预测由谁负责”。这就是评审那句追问的由来。

## 二、XGBoost 在做什么

XGBoost 是加法模型：预测值等于所有树的输出之和，每棵新树拟合当前模型还没解释掉的那部分梯度。[@chenXGBoostScalableTree2016]

$$
\hat y_i=\sum_{k=1}^{K} f_k(\mathbf x_i),\qquad
\mathcal L=\sum_i l(y_i,\hat y_i)+\sum_k\left(\gamma T_k+\tfrac12\lambda\lVert \mathbf w_k\rVert^2\right).
$$

损失函数用二阶泰勒展开近似，叶子权重有闭式解，正则项控制树的复杂度。这套设计让它在表格数据上又准又快，也带来了两个后果：树与树之间有交互，特征与特征之间也有交互。单看某个特征分裂了几次，无法还原“这一行”的账。

## 三、SHAP 记的是什么账

SHAP 把一次预测拆成“基准值加各特征贡献”，贡献用 Shapley 值定义：把特征逐个加入合作，计算边际收益在所有加入顺序上的平均。[@lundbergUnifiedApproach2017]

$$
\phi_i=\sum_{S\subseteq F\setminus\{i\}}\frac{|S|!\,(|F|-|S|-1)!}{|F|!}\Big[v(S\cup\{i\})-v(S)\Big].
$$

这个定义带来三条性质，正好对上解释场景的需要：

- **局部准确性**：$f(x)=\phi_0+\sum_i\phi_i$，各贡献加回去正好等于这条样本的预测。
- **缺失性**：没进入模型的特征贡献为零。
- **一致性**：模型改动后某特征的边际贡献若处处不减，它的 SHAP 值也不会变小。

通用 Shapley 值要枚举特征子集，代价随特征数指数增长。Tree SHAP 利用树结构，在多项式时间内算出与这个定义一致的结果，这也是 XGBoost 与 SHAP 能日常搭配的原因。[@lundbergFromLocalExplanations2020]

## 四、最小可用流程

```python
import shap
import xgboost as xgb

model = xgb.XGBRegressor(
    n_estimators=200, max_depth=5, learning_rate=0.1, random_state=42
).fit(X_train, y_train)

explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_test)   # 形状 (样本数, 特征数)

base = explainer.expected_value
assert abs(base + shap_values[0].sum() - model.predict(X_test[:1])[0]) < 1e-4
```

第三行不是装饰。先验证可加性，再去看图，能挡掉大部分“解释器用错对象”的错误。

分类任务要注意解释的是哪个空间。`TreeExplainer` 默认输出 `raw`，二分类时是 log-odds，不是概率；要直接解释概率，必须提供背景数据并切换到干预式扰动：

```python
explainer = shap.TreeExplainer(
    clf, data=background,
    feature_perturbation="interventional",
    model_output="probability",
)
```

只写 `model_output="probability"` 而不给 `data`，当前版本会直接报错：`Only model_output="raw" is supported for feature_perturbation="tree_path_dependent"`。网上不少示例省略了这个条件。

## 五、四张图，四个问题

| 图 | 回答的问题 | 读法 |
| --- | --- | --- |
| beeswarm（summary） | 整体上哪些特征在推动预测，方向如何 | 每点一条样本，横轴是 SHAP 值，颜色是特征值高低 |
| waterfall / force | 这一条预测怎样从基准走到最终值 | 从基准值开始，逐个加减贡献 |
| dependence | 单个特征与贡献是不是线性、有没有阈值 | 横轴特征值，纵轴 SHAP 值，可叠加第二个特征看交互 |
| bar | 平均绝对贡献的排序 | 与 `gain` 排序对照，差异本身是信息 |

第四张图常被当成“特征重要性”的替代品，其实两者回答不同问题：`gain` 说的是树怎么分裂，bar 图说的是模型输出对谁敏感。两者排序不一致很常见，不必强行解释成谁对谁错。

## 六、正负、绝对值、0

这是最容易读错的地方，需要拆成三件事。

| 维度 | 含义 | 假设的例子（基准 2.07，单位十万美元） |
| --- | --- | --- |
| 符号 | 相对基准推高还是拉低 | 面积贡献 $+0.50$，把预测往上推；房龄贡献 $-0.30$，往下拉 |
| 绝对值 | 对这条预测的影响强度 | $\lvert 0.50\rvert>\lvert 0.30\rvert$，面积影响更大 |
| 业务价值 | 这个方向对目标是否有利 | 卖房希望价格高，正贡献有利；风险模型希望违约低，负贡献有利 |

所以“高低”指的是模型输出相对基准的方向，不是特征值高低，也不是好坏。**SHAP 等于 0 不是“最好”，而是“中性”**：这个特征在这条样本上没有把预测推高或拉低。绝对值小说明影响弱，不说明模型更可靠。

分类任务还有一层：`raw` 空间的 SHAP 可以相加得到 log-odds，但 log-odds 到概率是 S 形变换，不是线性缩放。log-odds 从 0 增到 1，概率从 0.50 升到 0.73，同样的 $+1$ 在不同位置对应的概率变化并不相同。跨样本比较概率解释时，别把 log-odds 的差值直接当概率差。

## 七、我实际跑出来的几个数

用加州房价数据（八特征、80/20 划分、200 棵树、深度 5）跑了一遍，脚本在 `scripts/check_shap_xgboost.py`：

| 检查 | 结果 |
| --- | --- |
| 基准值 | 2.0718 |
| 可加性最大误差 | $5.25\times10^{-6}$ |
| `gain` 前五 | MedInc、AveOccup、Longitude、Latitude、HouseAge |
| 平均绝对 SHAP 前五 | Latitude、MedInc、Longitude、AveOccup、AveRooms |

两种排序的第一名就不一样。`gain` 更看重收入中位数带来的分裂收益，平均绝对 SHAP 更看重纬度的逐样本波动。这不是谁算错了，而是两个问题。

再看两个特征的关系。把同一列复制一份放进模型，平均绝对贡献是 $[1.583,\ 0.000]$：所有功劳记在被选中的那一列上，复制品一分没有。把两个高度相关的特征放进去，结果是 $[0.925,\ 0.828]$，份额不等但都很大。**这说明分摊取决于模型用了谁，不是数据里存在一个“真实份额”。** 想让读者知道“这两个变量共同起作用”，就不能只报其中一个的 SHAP。

最后是概率空间：干预式扰动加 `model_output="probability"` 时，概率上的可加性误差是 $8.28\times10^{-8}$；同一模型用 `raw` 解释 log-odds，误差是 $6.73\times10^{-5}$。两个空间都能加总，但加总的对象不同。

## 八、参数与陷阱

**扰动方式决定你解释的是哪个分布。** `tree_path_dependent` 是默认值，不需要背景数据，用训练时落在各节点的样本数当背景，快；`interventional` 需要 `data`，把特征替换成背景样本里的值，相当于假设特征相互独立，计算更贵，但语义更接近“如果这个特征换个值”。代价是它可能拼出训练集里不存在的特征组合，结论要按这个假设读。

**背景集会改变数字。** 干预式扰动的基准值来自背景样本的平均预测，抽 100 行和抽 1,000 行结果不会完全一样。报告里应写明背景集大小和抽样方式。

**近似开关有适用条件。** `approximate=True` 只在干预式扰动下有意义，用更少的背景样本来估贡献，换来速度，代价是数值偏差。默认的路径依赖模式本身就是精确算法，不需要这个开关。

**版本会变。** 上面的报错来自 shap 0.49.1 与 xgboost 2.1.4。旧教程里 `shap_values` 的返回形状、分类任务的数组维度、`probability` 的可用条件都可能不同，照抄代码前先看当前版本文档。

**解释的单位是模型输入。** 做了标准化、one-hot、分箱之后，SHAP 说的是变换后那一列，不是原始业务量。想回答“面积每多十平米值多少钱”，需要把变换反推回去，或者直接在原始尺度上建模。

## 九、SHAP 不能做什么

- **不是因果效应。** 它解释模型在给定数据分布下的行为；改变一个特征时其他特征会不会跟着变，SHAP 不回答。相关特征互相分摊，就是这件事的直接体现。
- **不是公平性证明。** 某个特征贡献小，不代表模型对该群体没有差别对待；代理变量可以把影响藏起来。
- **不能替代模型选择。** 解释一个预测很差的模型没有意义，先保证误差可接受。
- **跨模型比较绝对值要谨慎。** 不同模型、不同背景集、不同输出空间（raw 与 probability）算出的数值不可直接比大小。
- **不是反事实解释。** “如果面积多 20 平米会怎样”属于反事实问题，SHAP 给的是当前这条样本的分解。

## 十、用之前过一遍

- 先验证 `base + sum(shap) ≈ prediction`，确认解释器与模型对上了。
- 写明 `feature_perturbation`、背景集大小、`model_output`，以及软件版本。
- 分类任务明确解释的是 log-odds 还是概率，不要混着讲。
- 相关特征成组报告，别只挑份额最大的那个。
- 全局图与单样本图配合使用：前者定方向，后者讲故事。
- 把 SHAP 结论与误差分析、业务约束放在一起看，不要单独作为决策依据。

## 十一、证据边界

- 数值来自加州房价与乳腺癌数据集的单次划分，未调参、未做交叉验证，只用于演示机制，不代表这些数据上的最优表现。
- 脚本在 Python 3.9、xgboost 2.1.4、shap 0.49.1、scikit-learn 1.6.1 下运行；其他版本的行为可能不同。
- 本页不涉及因果推断、公平性审计或概率校准，相关结论不能从 SHAP 值直接推出。
