城市科学在解释人口、建筑、交通和公共服务时，需要先确定研究对象：什么构成一座城市，哪些关系维持城市生活，一个对象变化以后是否仍是同一个对象。对对象、关系和身份的这些选择构成研究的本体承诺。支持相关陈述的证据则属于认识论与研究方法问题，需要另外说明。

本文给出一套问题导向的分析框架，连接[[ontology|哲学本体论]]与知识工程中的形式本体。前者讨论存在者及其基本关系，后者把选定领域的类别、关系和公理明确表达。下面的分类与例子是教学性综合，可供具体问题修订。[SEP：Logic and Ontology](https://plato.stanford.edu/entries/logic-ontology/#Onto) · [W3C：OWL 2](https://www.w3.org/TR/owl2-overview/)

## 从一栋改变用途的建筑开始

设想以下虚构情境：一栋旧校舍经过改造，成为公共图书馆，由一家公共服务机构运营，按公布的时段开放。建筑档案、机构登记、开放安排和到访记录分别记录了这件事的不同部分。

如果要解释“图书馆服务如何形成”，至少需要分别考虑：

- **物理对象**：建筑、房间、入口及其位置。
- **行动者与组织**：工作人员、使用者和运营机构。
- **用途与活动**：某空间承担图书馆用途，具体发生借阅、阅读和维护活动。
- **制度安排**：谁获得运营授权，哪些使用规则适用，谁承担责任。
- **变化与证据**：改造和启用发生于何时，当前用途与开放状态由什么记录支持。

这几个方面共同解释同一处城市空间。组织、角色、规范与持续实践也是社会制度分析的重要对象，识别它们需要机构职责、规则与实践方面的证据。[SEP：Social Institutions](https://plato.stanford.edu/entries/social-institutions/)

## 城市科学承认哪些对象

可以先按对象在解释中的作用作如下区分。它们是建模时的分析类别，具体实现可以组合、细分或采用其他术语。

| 类别 | 城市中的例子 | 需要说明的问题 |
| --- | --- | --- |
| 物质对象与环境 | 建筑、道路、水体、地形 | 对象怎样识别，位置和组成怎样记录？ |
| 人与组织 | 居民、家庭、企业、管理机构 | 个体、群体和组织分别如何界定？成员关系何时有效？ |
| 角色、用途与服务 | 租户、运营者、校舍用途、图书馆服务 | 由谁或什么承担，在什么条件和时段成立？ |
| 关系与网络 | 连接、通勤、交易、运营、授权 | 起点、终点、方向和适用范围是什么？ |
| 活动、事件与过程 | 一次出行、启用、迁移、建设、制度变迁 | 如何划分发生、持续和结束，过程如何改变对象？ |
| 规则与制度 | 使用资格、产权安排、规划分类 | 由什么组织与程序维持，适用于谁和何处？ |
| 空间范围 | 地块、街区、行政区、功能城市区 | 边界依据什么规则和版本生成？ |
| 观测与模型结果 | 到访计数、测量、调查、模拟输出 | 记录了谁或什么，采用什么方法，覆盖什么时空？ |

这张表让不同城市科学问题的对象选择更容易比较。城市形态分析关注物质配置；网络分析关注连接与流动；制度研究关注角色、规则和行动条件。Batty 关于城市科学的论述把网络、互动、移动过程与形态联系起来，为同时考虑对象和过程提供了一个具体入口。[@battyBuildingScienceCities2012]

这些视角可以围绕同一个问题协作。例如，解释图书馆的使用状况，需要把空间容量、开放安排、交通连接和使用规则联系起来，同时说明每一部分能够支持什么结论。

## 关系使对象进入解释

“位于”“部分组成”“运营”“拥有”和“发生于”表达不同关系。建筑可以位于某个行政区，机构可以运营某项服务，一次借阅可以发生在一个地点和时段。关系名称、方向和时间条件决定模型实际表达了什么。

进一步分析网络时，还要说明连接的含义：道路连接表示通行结构，通勤连接表示一定时期内的出行联系，机构合作连接表示一种组织安排。它们可以形成不同的图，边的证据与单位也分别定义。

因果主张需要额外的机制和识别证据。把某处标为“相邻”只表达空间关系；若要解释图书馆启用对周边活动的影响，还需要比较条件、时间顺序及其他可能解释。有关这一层判断，可接着阅读 [[causality|因果性]] 与 [[mechanism|机制]]。

## 城市边界也是对象定义的一部分

“城市”可以依据行政管辖、人口聚集或功能联系划定。同一建筑可能同时属于一个行政城市、一个连续聚集区域和一个更大的通勤联系区域。

OECD 的城市与功能城市区方法说明了这种差别：城市识别使用人口密度和格网连续性，功能城市区（FUA）进一步纳入通过工作通勤形成经济联系的周边区域。[OECD 定义说明](https://www.oecd.org/en/data/datasets/oecd-definition-of-cities-and-functional-urban-areas.html)

边界选择会影响人口、就业、服务数量等统计量的范围和分母。因此，模型里的 `UrbanArea` 至少应关联边界几何、定义方法、数据时期和版本。行政隶属与功能联系可以作为不同关系保存，便于说明各自支持的问题。空间单元变化的统计后果见 [[../Data/maup-and-gerrymandering|MAUP]]。

## 时间决定什么延续、什么改变

在旧校舍案例中，可以约定改造后建筑身份延续，同时记录新的用途、运营关系和生效时间。这是一项需要说明的身份判定：若对象被拆除、合并或重建，就要重新检查身份是否延续，以及不同档案标识怎样对应。

用途适合带上有效时段。把“建筑 B 在一段时期承担图书馆用途”单独表达，可以同时保留早先的校舍用途和后续变化；机构更换时，也能更新运营关系而保留建筑记录。

OGC CityGML 3.0 为城市地理对象提供语义信息模型，其 Versioning 模块表达对象与模型版本变化，Dynamizer 模块关联属性的时变值。这些机制可帮助组织空间对象及其变化；涉及机构身份、权利和服务规则时，仍需补充相应领域定义。[CityGML 3.0，§7.6 与 §7.13](https://docs.ogc.org/is/20-010/20-010.html)

## 把观测与被观测的城市对象分开

一条到访记录描述一次被系统记录的活动，一个日计数描述规定时段内按某种规则得到的数量。解释它们时，需要知道采集方式、覆盖入口、重复计数处理和时间范围。由这些记录推断使用人数，还要说明怎样从记录对应到人。

SOSA/SSN 将观测、关注对象、被观测属性、方法、结果和时间分别表达，可以用来组织这类证据。例如，一次室内温度观测应关联具体空间、温度属性、测量过程、结果和单位，而空间本身具有另一套身份与关系。[W3C：SOSA/SSN](https://www.w3.org/TR/vocab-ssn/)

将证据关系放进模型，可以继续区分实测、调查报告和模拟估计。来源不一致时，先保留各自的对象、方法与时期，再判断能否比较或合并。

## 把分析写成一个最小领域模型

下面用八类概念组织旧校舍案例，作为练习模型：

| 类 | 在此教学模型中的职责 |
| --- | --- |
| `Building` | 表示具有持续身份的物理建筑 |
| `Organisation` | 表示承担运营等职责的组织 |
| `Service` | 表示借阅服务、阅览服务及其安排 |
| `UseAssignment` | 将建筑、用途和有效时段联系起来 |
| `Event` | 表示改造、启用或停用等发生项 |
| `UrbanArea` | 表示按某种规则与版本确定的空间范围 |
| `Observation` | 表示针对对象某属性作出的观测 |
| `EvidenceRecord` | 表示支持用途、事件或规则判断的记录及来源 |

关系可以先写成以下可读形式。它们是类型之间的结构示意，尚未形成可执行的标准本体或实例数据库。

```text
Organisation ── operates [有效时段] ──> Service
Service ── providedAt ──> Building
UseAssignment ── appliesTo ──> Building
UseAssignment ── supportedBy ──> EvidenceRecord
Building ── locatedIn ──> UrbanArea
Event ── affects ──> Building
Observation ── observes ──> Building
```

其中 `UseAssignment` 还需要用途名称与起止时间，`Observation` 需要属性、过程、结果与时间。实际观测若针对某个房间，应补充空间部件。`operates` 同时记录关系的有效时段；在 RDF 等具体表示中，可以进一步将这类带属性的关系建成独立的关联对象。

接下来用具体问题检查模型：

| 要回答的问题 | 必须明确的概念和证据 |
| --- | --- |
| 在时间 T，这栋建筑承担什么用途？ | 建筑身份、用途分配、有效时段、支持记录 |
| 谁在时间 T 运营这里的服务？ | 组织、服务、提供地点、运营关系及其有效期 |
| 统计“本市服务数量”采用哪一范围？ | 城市定义、边界版本、计数对象与去重规则 |
| 一项温度或到访结果从哪里来？ | 被观测对象、属性、方法、结果、单位与时段 |

这些问题也揭示当前简化模型的范围。若目标涉及家庭决策、土地市场、生态过程或居民对场所的意义，需要按目标扩展相应的概念、关系与证据。

## 形式化之后如何检查

可以使用 [[../tools/ontology-playground|Ontology Playground]] 画出小模型、检查关系方向并导出其支持的 RDF/XML。把模型进一步交给标准工具时，需要分别安排三类检查：

1. **表达检查**：类、实例、属性、时间和标识是否按约定组织，交换文件能否正确解析。
2. **逻辑与数据检查**：OWL 推理用于检查相应公理与推论；SHACL 用于检查指定数据条件。例如，要求每条用途记录有开始时间，需要明确相应数据约束及适用对象。
3. **经验与解释检查**：用途记录是否反映现实，观测是否覆盖所讨论对象，模型提出的机制是否得到独立证据支持。

OWL 的开放世界语义允许未记录事实仍处于未知状态；SHACL 可针对当前数据图检查指定条件。两者的结果都需要按照实际公理、约束和输入解释。[OWL 2 Primer](https://www.w3.org/TR/owl2-primer/) · [SHACL](https://www.w3.org/TR/shacl/)

## 本体分析给城市科学留下什么

最终需要交付的是一套可说明的对象与关系定义：哪些对象进入研究，依据什么条件识别，如何持续或变化，边界怎样确定，哪些证据支持哪些陈述。这使数据整合、模型比较与理论讨论拥有明确的接口。

模型的公开说明还应保留范围：哪些服务、活动和群体被记录，哪些经验与制度条件尚未表达。由此，概念体系可以随着问题和证据修订；城市研究中的理论分歧也能落到具体的定义与解释选择上。
