类型与属性

Building

建筑：具有持续身份的物理对象。用途改变时，是否保持同一建筑标识需要另行约定；本模型不把建筑与运营机构合并。

buildingId string
建筑标识的字段定义；不包含任何真实标识值。
name string
建筑名称。
lifecycleStatus enum
建筑生命周期状态。 可选值：existing、altered、demolished、unknown
geometryReference string
指向几何表达的引用；当前没有坐标或几何实例。
crs string
几何所用坐标参考系。

Organisation

组织：承担服务运营等职责的组织，与其使用的物理建筑分别识别。

organisationId string
组织标识字段。
name string
组织名称。
organisationType string
组织类型及其判定口径。

Service

服务：如借阅服务、阅览服务及其安排；与一次具体借阅活动区分。一个服务可在多个地点提供，一个建筑也可承载多项服务。

serviceId string
服务标识字段。
name string
服务名称。
serviceKind string
服务类别及定义。
openingSchedule string
开放安排，需包括日期与例外说明。
timeZone string
开放安排采用的时区。
accessRule string
服务的使用条件与规则依据。

UseAssignment

用途分配：把建筑、用途和有效时段联系起来。结束时间缺省需结合endStatus解释，不自动意味着仍有效。

assignmentId string
用途分配标识字段。
useName string
用途名称；例如校舍或公共图书馆仅是教学情境。
validFrom datetime
用途开始生效的时刻。
validTo datetime
用途结束生效的时刻，可尚未登记。
endStatus enum
明确区分持续、已结束与未知。 可选值：ongoing、ended、unknown
assertionStatus enum
用途判断的证据状态。 可选值：reported、verified、disputed、unknown

Event

事件：改造、批准、启用或停用等发生项。事件与支持事件判断的文档分别表示。

eventId string
事件标识字段。
eventType string
事件类型及判定条件。
startsAt datetime
事件开始时刻。
endsAt datetime
事件结束时刻。
description string
事件说明及适用范围。

UrbanArea

城市范围：按行政、形态或功能规则确定的空间范围。一个建筑允许关联多套范围；比较统计量时保留定义与边界版本。

areaId string
空间范围标识字段。
name string
范围名称。
definitionType enum
行政、形态或功能界定。 可选值：administrative、morphological、functional
definitionMethod string
界定规则及数据来源。
boundaryVersion string
边界版本与时期。
validFrom datetime
该版本的适用起点。
validTo datetime
该版本的适用终点，未知需明确标注。
geometryReference string
边界几何引用；当前没有真实边界数据。

Observation

观测：本图限定建筑层级的属性或汇总观测。房间温度需扩展房间类型并指定对象；观测与承载结果的记录分别识别。

observationId string
观测标识字段。
observedProperty string
被观测属性与统计口径。
procedure string
采集、抽样或计算方法。
resultValue string
结果的文本表示；进行数值计算前还需类型与单位检查。
unit string
结果单位及计数口径。
phenomenonTime datetime
被观测现象的时间。
resultTime datetime
结果形成或登记的时间。
targetScope string
明确对象层级、覆盖与聚合范围。

EvidenceRecord

证据记录：支持用途、事件或观测判断的文档和来源。记录存在与判断已经证实分别说明。

recordId string
记录标识字段。
recordType string
档案、公告或测量记录等类型。
sourceTitle string
来源标题。
sourceURI string
可追溯来源的地址字段；当前不包含真实记录地址。
issuedAt datetime
发布或形成时间。
accessedAt datetime
查阅时间。
status enum
记录版本与可用状态。 可选值：available、superseded、disputed、unknown

关系与时间条件

  • 运营：organisation → service；many-to-many。组织在有效时段内运营服务。关系属性validFrom、validTo、endStatus说明时间条件；缺省结束时刻需要解释。 关系属性：validFrom (datetime)、validTo (datetime)、endStatus (string)
  • 提供地点：service → building；many-to-many。服务在建筑中提供；允许一项服务有多个地点及一栋建筑提供多项服务。 关系属性：validFrom (datetime)、validTo (datetime)
  • 用途对应建筑：useAssignment → building；many-to-one。每条用途分配预期针对一个建筑；many-to-one只表达最大数量方向，必填性需另行验证。
  • 用途证据来源：useAssignment → evidenceRecord；many-to-many。将用途分配与支持该判断的证据记录关联。此关系与事件证据关系使用不同标识。
  • 位于范围内：building → urbanArea；many-to-many。允许同一建筑对应行政、形态、功能等多套范围。范围的定义、边界版本与适用期由UrbanArea记录。 关系属性：asOf (datetime)
  • 事件涉及建筑：event → building；many-to-many。事件与其涉及的建筑相联系；这条边不自动表达因果识别结论。
  • 对应用途变更：event → useAssignment；many-to-many。在有证据时，将改造或启用事件与相应的用途分配关联。
  • 事件证据来源：event → evidenceRecord；many-to-many。将事件判断与证据记录关联，与用途证据关系分别建模。
  • 观测建筑：observation → building；many-to-one。本练习限定一条观测针对一栋建筑的属性或汇总指标；观测时间、方法、结果与单位由Observation记录。
  • 观测记录来源：observation → evidenceRecord；many-to-many。区分观测过程／结果与承载它们的文档记录；记录数量不等同人数或活动次数。
